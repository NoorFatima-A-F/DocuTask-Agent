---

## 1. Classification Definitions

Every reported metric, benchmark, latency value, and cost figure across all audit documentation is strictly tagged with exactly one of the following classifications:

1. **`[MEASURED]`**: Obtained from direct runtime execution on a real codebase implementation.
2. **`[REPLAYED]`**: Reproduced from previous empirically measured execution runs.
3. **`[DERIVED]`**: Mathematically calculated from measured empirical values (e.g., F1 Score, ECE Error, Amdahl Speedup).
4. **`[SIMULATED]`**: Generated by controlled simulation scenarios (e.g., fault injections, soak load testing).
5. **`[ESTIMATED]`**: Derived from analytical cost models, capacity projections, or theoretical bounds.

---

## 2. Standard Rules

- No metric may omit its evidence classification tag.
- Perfect 10/10 or 100% scores are prohibited for unverified cloud conditions or analytical estimations.
- Any metric relying on simulation or projection must explicitly document its underlying assumptions and operational limitations.
